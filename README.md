# 부검참관보고서 — 「긴 평화」의 죽음

병원 수술실에서 1인칭으로 진행하는 부검 참관. 단일 HTML 프로토타입을
Vite + Three.js 로 이전한 뒤, 1인칭 게임으로 개조한 것이다.
보고서 본문과 4단계 진행(외표검사 → 내부검사 → 37일 → 사인판정)은 원본 그대로다.

## 실행

```bash
npm install
npm run dev
```

`npm install` 이 끝나면 `postinstall` 이 DRACO 디코더를 `public/draco/` 로 복사한다.

## 조작

| 키 | 동작 |
| --- | --- |
| `W A S D` | 이동 (`Shift` 뛰기) |
| 마우스 | 둘러보기 (화면을 클릭하면 포인터 잠금) |
| `E` | 조준한 부위 검안 — 그 부위 시점으로 얼굴을 들이민다 |
| `F` | 다음 단계 (개복하기 / 다음 날짜 / 판정서 작성) |
| `Tab` | 클립보드(서류철) 접기·펼치기 |
| `Esc` | 포인터 잠금 해제 |

사인 판정 단계에서는 자동으로 마우스가 풀려 판정서를 직접 채울 수 있다.

## 자동 검증

```bash
npm run verify
```

vite 개발 서버를 코드에서 직접 띄우고, 설치된 크롬을 헤드리스로 붙여
**전 과정을 실제 게임 경로로 통과시킨다** — 총상 조준·검안 → 개복 →
세 계통 검안 → 37일 경과 → 판정서(오답 한 번 포함) → 최종 도장.
단계마다 상태를 검사하고 스크린샷을 `verify/shots/` 에 남긴다.
하나라도 실패하면 종료 코드 1.

조준은 진짜로 광선을 쏴서 맞힌다. 부위가 다른 부위에 가려 조준 불가능해지면
그 자리에서 실패한다 — 눈으로 확인하지 않아도 회귀를 잡아낸다.

- `VERIFY_HEADED=1` 창을 띄운 채 실행
- `CHROME_PATH=<경로>` 크롬 실행 파일 지정

## 배포 (GitHub Pages)

`.github/workflows/deploy.yml` 이 `main` 브랜치에 push 될 때마다 빌드해서 Pages 에 올린다.
저장소 이름을 읽어 `base` 를 자동으로 맞추므로(`/<저장소>/`, 사용자 사이트면 `/`),
하위 경로에서도 `models/body.glb` 와 `draco/` 가 제대로 잡힌다.

처음 한 번만:

1. GitHub 에서 빈 저장소를 만든다 (이름은 ASCII 권장 — 예: `long-peace-autopsy`).
2. `git remote add origin <저장소 URL>` → `git push -u origin main`
3. 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 바꾼다.

이후 push 할 때마다 자동 배포되고, 주소는 `https://<아이디>.github.io/<저장소>/` 다.

배포 전 확인:

```bash
npm run check:dist
```

빌드한 `dist` 를 하위 경로에서 서빙해 `glb`·DRACO 디코더가 실제로 200 으로 오는지,
4xx 나 페이지 오류가 없는지 본다(`BASE_PATH=/autopsy/ npm run build` 로 빌드한 뒤 실행).

## 성능 측정

```bash
npm run perf
```

크롬 창을 띄우고 **실제로 방 안을 걸어 다니는 상태**에서 픽셀 비율별 프레임 타임을
잰다(예열 후 두 번 재고 뒤엣것만 취한다). 마지막 줄은 적응 해상도를 켠 채로
어디에 안착하는지 보여 준다. 프레임 문제인지 아닌지를 눈이 아니라 숫자로 가르기 위한 도구다.

## 모델 교체

`public/models/body.glb` 를 놓기만 하면 된다. 메시 이름을
`SKIN_TORSO` / `SKIN_LIMBS` / `BONE` / `VESSEL`(또는 `HEART`) / `NERVE`
(+선택 `WOUND`)로 맞추면 부위 매핑·조준 판정·시점 프리셋이 전부 자동으로 따라온다.
자세한 규약은 [public/models/README.md](public/models/README.md).

파일이 없거나 이름 규약에 맞는 메시가 하나도 없으면 콘솔에 사유를 남기고
프리미티브 마네킹으로 폴백한다 — 그 상태로도 전 단계가 정상 동작한다.

dev 서버에서는 `window.__autopsy` 로 `model`·`player`·`stage`·`S`·`api` 를
콘솔에서 들여다볼 수 있다. 프로덕션 빌드에서는 제거된다.

## 원본에서 달라진 점

- **1인칭 수술실.** 궤도 카메라 대신 방 안을 걸어 다닌다. 부위를 조준해 `E` 로
  검안하면, 부위 바운딩박스에서 계산한 시점까지 카메라가 미끄러져 들어간다
  (원본의 카메라 프리셋이 1인칭의 "들여다보기"로 옮겨 온 것이다).
  둘러보기 시작하면 원래 서 있던 자리로 돌아온다.
- **서류철이 게임 안으로.** 오른쪽 2단 패널 대신 아래에서 올라오는 클립보드.
- **부위 좌표 하드코딩 제거.** 시점의 중심과 거리는 부위 바운딩박스에서 계산한다
  (`bodyModel.buildViews`). 화면 종횡비가 바뀌면 다시 계산한다. 기하만으로 정할 수
  없는 "보는 각도"만 `parts.js` 의 `VIEW_ANGLES` 에 남겼다.
- **출혈 표현이 프래그먼트 단위.** 원본은 메시마다 총상까지의 거리를 미리 재
  머티리얼 색을 갈아 끼웠다. glb 는 몸 전체가 메시 두어 개일 수 있어서,
  표피 머티리얼에 셰이더 항을 주입해 픽셀 단위로 번지게 했다.
- **계통 히트박스 자동 생성.** 얇은 관·뼈를 조준할 수 있게 만드는 투명 박스를
  각 계통 바운딩박스에서 만든다(원본은 좌표 하드코딩).
- **픽 우선순위.** 최근접이 아니라 ① 총상(외표검사 단계에서만) → ② 계통(겹치면
  바운딩박스가 작은 쪽) → ③ 표피 순이다. 전신 골격처럼 큰 부위가 그 안의
  심장·신경을 삼키는 것을 막고, 개복 후 반투명해진 표피가 계통 조준을 가리지 않게 한다.
- **바닥·벽 지직거림 대책.** 1인칭은 화면 전체가 늘 움직여서 표면 에일리어싱이
  그대로 깜박임으로 보인다. `antialias: true`(MSAA)는 기하 외곽선만 잡고 표면 내부는
  못 잡는다. 이방성 필터링(GPU 최대)과 타일 무늬 완화(줄눈을 굵고 옅게, 타일을 크게)로
  잡았다. **초과표본은 쓰지 않는다** — 픽셀 수가 배로 늘어 프레임이 무너지는데
  (dpr 1.5 화면에서 36fps, 프레임의 전부가 20ms 초과) 깜박임 감소는 그만큼 크지 않았다.
- **적응 해상도.** 창 크기도 GPU 도 알 수 없으므로, 화면 물리 해상도에서 시작해
  프레임이 밀리면 한 단계씩 낮추고 여유가 생기면 되올린다(`stage.js`).
  중앙값만 보면 놓치는 구간이 있어서(중앙값 16.7ms 인데 프레임의 27%가 20ms 초과)
  느린 프레임 비율도 함께 본다. `npm run perf` 로 실측할 수 있다.
- **조준 성능.** 고해상도 glb(18만 삼각형 기준)에서는 레이캐스트 한 번이
  프레임 예산을 넘는다. 조준 판정을 프레임당 한 번으로 합치고, 부위 바운딩박스로
  먼저 걸러 몸을 빗나간 광선은 메시 검사를 건너뛴다.
  더 무거운 모델을 쓸 거라면 `three-mesh-bvh` 를 붙이는 것이 다음 수순이다.
- **부위마다 자기 머티리얼을 갖는다.** glb 는 여러 부위가 머티리얼 하나를 공유하는
  일이 흔하다(실제로 받은 모델이 표피·뼈·심장·신경을 한 머티리얼로 썼다). 그대로 두면
  개복 때 표피를 반투명하게 만든 설정이 장기까지 투명하게 만들고, 출혈 색도 장기에
  번진다. 부위 등록 시점에 머티리얼을 복제한다(같은 부위 안에서는 계속 공유).
- **몸은 양면으로 그린다.** 손으로 만든 해부 모델은 미러링한 반쪽의 노멀/와인딩이
  뒤집힌 경우가 흔하다. 앞면만 그리면 그 반쪽이 통째로 컬링돼 사라지고 그림자만
  남는다(실제로 처음 받은 glb 가 그랬다). 근본 수정은 모델 쪽에서 하는 편이 좋고,
  방법은 [public/models/README.md](public/models/README.md) 에 적어 두었다.
- **금속 검안대를 위한 환경맵.** 검안대는 metalness 0.92 라 반사할 환경이 없으면
  그림자 속에서 완전한 검정이 된다(금속은 확산광이 없어 앰비언트가 닿지 않는다).
  씬의 조명과 같은 모양의 아주 어두운 환경을 PMREM 으로 구워 넣어 해결했다.
  밝은 기성 환경맵을 쓰면 수술실 톤이 날아간다.
- **개복하면 표피 그림자를 걷는다.** 17% 불투명이 된 몸이 실루엣 그림자를 그대로
  드리우면 거짓말이 되고, 검안대에 찍힌 그 그림자가 몸 너머로 비쳐 얼룩이 된다.
- **three r128 → 최신 API.** `outputEncoding`→`outputColorSpace`,
  그리고 r155 이후 punctual light 가 물리 단위로 바뀐 것에 맞춰 spot/point
  세기에 π를 곱했다. r128 에는 색 관리가 없어 16진 팔레트가 선형값으로 쓰였으므로,
  이전해 온 색만 `palette.js` 의 `lin()` 으로 선형 고정해 원본 톤을 유지한다
  (`ColorManagement` 는 켜 둔 채라 glb 텍스처는 정상 경로를 탄다).

### 고친 버그

원본에서는 **총상을 클릭할 수 없었다.** 총상 구체(반지름 0.024)가 흉부 실린더
안쪽에 완전히 묻혀 있어 레이캐스트가 항상 표피를 먼저 맞았고, 그 결과
"개복하기" 버튼이 열리지 않아 1단계에서 진행이 멈췄다(원본 HTML 에서 화면 전
좌표를 훑어도 `흉부 관통상` 툴팁이 한 번도 뜨지 않는다).
계통 히트박스와 같은 방식으로, 총상 지점에 표면 밖까지 나오는 투명 히트 스피어
(`HIT_WOUND`)를 두어 해결했다. 총상 표식 자체도 비율로 찍지 않고 표피 표면에
광선을 쏘아 붙인다 — 비율로 찍으면 모델에 따라 몸 안에 묻힌다.
